## 1. Prepare the RobotStudio workspace

The recorded workspace already contained an IRB1200_5_90 virtual controller, a table, six blocks, two color-matched bins, and a simulated suction tool. The station and its project-specific bridge were prepared before Kinex onboarding. These station and bridge files are separate from the standard Kinex installation; the steps below summarize how that integration was assembled.

On Windows, open the saved RobotStudio station with its bridge add-in. Load the RAPID motion module and check that the virtual controller is in Auto mode with motors on. The bridge used here rejects physical controllers.

In WSL Ubuntu, [install Kinex](/docs/#install-and-run) and open the shared workspace containing the Python bridge client, `abb.py`. Check the connection before starting the agent:

```sh
python3 abb.py scene
```

A fresh response should identify the virtual controller and report the tool position, six blocks, matching bin slots, and whether an object is held.

## 2. Expose the simulator through a bridge

The Python client exchanges JSON request and response files with a C# RobotStudio add-in through a shared directory. The add-in reads the station through the RobotStudio SDK and sends RAPID `MoveL` or `MoveJ` commands to the virtual controller. This connection uses the existing ABB controller and SDK directly.

For this task, the bridge exposes scene reads, Cartesian motion, object attachment and release, snapshots, station saving, and stopping. Positions use meters in the station coordinate frame. Motion requests wait for controller completion and check the resulting tool position before returning.

Kinex onboarding wraps that connection in two [devices](/docs/devices/):

| Device | Role in this integration |
| --- | --- |
| `abb`, type `other` | The custom interface for Cartesian motion, scene reads, simulated grasp/release, and station operations. Joint positions are observations; this bridge does not expose joint-position commands. |
| `world`, type `world` | Host-clock reads and waiting. The bridge exposes no simulator clock or step operation, so this device provides wall-time pacing. |

## 3. Onboard the existing connection

Start Kinex from the shared workspace. The recording uses:

```sh
kinex --auto --provider openai --model gpt-6-astra --thinking high
```

Give [onboarding](/docs/onboarding/#onboarding) the task and the existing connection details. A concise version of the recorded request is:

```text
/onboarding Prepare this ABB RobotStudio IRB 1200 simulation for sorting
six red and blue blocks into matching bins. Read the task instructions,
abb.py, and the RobotStudio bridge. Reuse the running virtual controller
and existing connection. Inspect the live scene, register the supported
devices, and verify them before sorting.
```

Kinex inspects the client and bridge, records the workspace and device profiles under `.kinex/`, prepares drivers, then loads and checks the connection. In this run, verification covered a live scene read, controller status, host-clock behavior, and an idle stop acknowledgement. The station supplied the geometry needed for sorting, so no camera calibration was performed.

## 4. Sort and verify

After onboarding, ask Kinex to sort all six blocks by their observed colors, verify each placement, and save the final scene and station.

For each block, the agent reads the live scene, selects a free slot in the matching bin, approaches above the block, descends and attaches it, lifts before moving sideways, then lowers and releases it at the slot. It reads the scene again to check the actual placement before continuing.

The recorded final check reports **six correctly sorted, zero in the wrong bin, and no object held**. The workspace retains the device profiles and drivers, so later sessions can reopen the station and bridge, load the devices, and check the connection with `/ping all`.

This example uses simulator metadata for object colors and positions, plus kinematic suction attachment. It does not model contact forces or slipping. Collision checks sample the robot against the table and bin walls; the recording demonstrates the simulation integration and task workflow.
