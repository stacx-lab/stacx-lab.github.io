## 1. Prepare the simulation

This example starts with a prepared IRB1200_5_90 station, six blocks, two bins, and a simulated suction tool. The station, bridge add-in, and `abb.py` client are project-specific prerequisites, not bundled with Kinex.

Open the station and add-in in RobotStudio with the RAPID motion module loaded and the virtual controller in Auto mode. The bridge accepts only virtual controllers.

In WSL Ubuntu, [install Kinex](/docs/#install-and-run), open the shared workspace, and check the connection:

```sh
python3 abb.py scene
```

The response should report controller status, tool position, blocks, bin slots, and whether an object is held.

## 2. Connect the bridge

The Python client exchanges JSON files with a C# RobotStudio add-in through a shared directory. The add-in reads the station through the RobotStudio SDK and sends RAPID `MoveL` or `MoveJ` commands to the virtual controller.

Positions use meters in the station frame. Each motion request waits for controller completion and verifies the tool position before returning. Onboarding wraps the connection in two [devices](/docs/devices/):

| Device | Role in this integration |
| --- | --- |
| `abb` (`other`) | Cartesian motion, scene reads, simulated grasp/release, snapshots, save, and stop. Joint positions are read-only. |
| `world` (`world`) | Host-clock reads and waiting; the bridge exposes no simulator clock or stepping. |

## 3. Onboard in Kinex

Start Kinex from the shared workspace with the recorded settings:

```sh
kinex --auto --provider openai --model gpt-6-astra --thinking high
```

Give [onboarding](/docs/onboarding/#onboarding) the task and connection details:

```text
/onboarding Prepare this ABB RobotStudio IRB 1200 simulation for sorting
six red and blue blocks into matching bins. Read the task instructions,
abb.py, and the RobotStudio bridge. Reuse the running virtual controller
and existing connection. Inspect the live scene, register the supported
devices, and verify them before sorting.
```

Kinex inspects the bridge, saves profiles and drivers under `.kinex/`, and checks the devices. This run verified scene reads, controller status, host-clock behavior, and an idle stop acknowledgement. Sorting used station geometry, so no camera calibration was needed.

## 4. Sort and verify

Ask Kinex to sort all six blocks by color, verify each placement, and save the final scene and station.

For each block, the agent reads the scene, selects a free slot in the matching bin, picks the block, lifts before lateral travel, then lowers and releases it. A fresh scene read confirms placement before the next pick.

The final check reports **six correctly sorted, zero in the wrong bin, and no object held**. To reconnect later, reopen the station and bridge, start Kinex in the same workspace, load the devices, and run `/ping all`.

The example uses scene metadata and kinematic suction attachment, without contact-force or slip simulation. Collision checks sample the robot against the table and bin walls.
